Official Linux API and kernel documentation for the container mechanism.
namespaces(7): namespace types (cgroup, IPC, network, mount, PID, time, UTS,
user), created or joined via the CLONE_NEW* flags of clone(2)/unshare(2)/
setns(2); each namespace wraps a global kernel resource so processes inside
appear to have their own isolated instance. pid_namespaces(7): PIDs can
repeat across namespaces and start at 1 in a new namespace. mount_namespaces
(7): isolation of the list of mounts. network_namespaces(7): isolation of
network devices, stacks, ports. user_namespaces(7): uid_map/gid_map UID/GID
mapping, root-without-host-privilege semantics. cgroups(7): cgroup v2 single
unified hierarchy, controllers (cpu since Linux 4.15, memory, io, pids), v2
memory controller files (memory.max, memory.high) and cpu controller
(cpu.max, cpu.weight). chroot(2): changes only the root directory; does not
change the working directory or isolate mounts; superuser can escape a chroot
jail ("mkdir foo; chroot foo; cd .."). pivot_root(2): moves old root to
put_old and makes new_root the root; documented use: setting up a root
filesystem during container creation. Kernel OverlayFS documentation
(docs.kernel.org/filesystems/overlayfs.html): lowerdir/upperdir/workdir
combined into a merged view; copy-up on first modification of a lower-layer
file; multiple colon-separated lower layers.
