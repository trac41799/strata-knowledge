Industrial experience paper from Google on latency variability in
large-scale web services: variability (background activity, failures,
scheduling) is inherent and cannot be eliminated, so responsive services
need software techniques that tolerate the tail. Key results: with query
fan-out to N independent components, end-to-end latency is set by the
slowest one — e.g., 100 sub-requests each slow 1% of the time yield a 63%
probability that at least one is slow (1 - 0.99^100); means hide the tail,
and high percentiles (p99, p99.9) are the operative measures. Documents
tail-tolerant techniques with measured cost/benefit — hedged requests cut
a BigTable benchmark's 99.9th-percentile latency from 1800 ms to 74 ms
while adding ~2% request load; tied requests, probe-and-queue,
micro-partitions, selective replication, and latency-induced probation —
and the ~100 ms user-perceived "fluid" responsiveness target. Web-verified
via ACM/Semantic Scholar/Google Research publication page and multiple
detailed summaries (accessed 2026-08-19).
