Defines data leakage as the introduction of information that is not
legitimately available at prediction time, via two channels: features (an
input x that encodes information about the target y) and training samples
(instances that should not be available when the model is learned). Shows that
leaked models can achieve near-perfect cross-validated performance while
failing in deployment, and proposes prevention via "learn-predict separation":
tagging each sample by whether x is legitimate for inferring y and excluding
illegitimate features. Verified via publisher record and citing literature
(doi 10.1145/2382577.2382579).
