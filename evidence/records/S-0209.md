Canonical practitioner text on test-driven development. States the two rules —
(1) write new code only if an automated test has failed; (2) eliminate
duplication — which yield the red/green/refactor cycle: write a small failing
test (red), make it pass with the simplest change (green), then refactor
duplication away. Beck frames TDD as a development and design discipline
(tests as executable specifications driving incremental design), not merely
as a testing technique; quality claims in the book are presented as practice
experience rather than controlled experimental evidence. Web-verified:
publisher/Amazon records (ISBN 978-0-321-14653-3, Addison-Wesley, Nov 2002)
and the red/green/refactor definition quoted in multiple secondary sources
(e.g., martinfowler.com/bliki/TestDrivenDevelopment.html).
