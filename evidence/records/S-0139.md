Practitioner book on making change safe in legacy codebases. Introduces the
seam model (Chapter 4): a seam is "a place where you can alter behavior in
your program without editing in that place," and each seam has an enabling
point where the decision to use one behavior or another is made. Defines
legacy code as code without tests and motivates seams as the mechanism for
sensing and separating behavior before changing it. Web-verified: Prentice
Hall 2004, ISBN 0131177052; seam definition quoted in multiple secondary
sources (understandlegacycode.com; martinfowler.com "LegacySeam").
