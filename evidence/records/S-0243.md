Internet Standard defining the OAuth 2.0 authorization framework: a third-party
application obtains limited access to an HTTP service on behalf of the resource
owner (or on its own behalf) without holding the owner's credentials. Defines four
roles (resource owner, client, authorization server, resource server), four grant
types (authorization code, implicit, resource owner password credentials, client
credentials), access tokens (credentials with specific scope and lifetime, usually
opaque to the client) and refresh tokens (credentials used to obtain new access
tokens, never sent to resource servers). In the authorization code grant (Sec.
1.3.1, 4.1) the resource owner authenticates only at the authorization server and
the access token is delivered directly to the client; in the implicit grant
(Sec. 1.3.2) the access token is issued directly and the authorization server does
not authenticate the client. How the resource owner authenticates is explicitly
beyond scope (Sec. 3.1); TLS is required on the authorization endpoint (Sec. 3.1);
security considerations include CSRF via the "state" parameter (Sec. 10.12).
